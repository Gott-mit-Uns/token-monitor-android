## 已接受的方向和约束

- 先统一默认字体，再考虑增加更多可选字体。
- Inter 用于普通界面及总量；JetBrains Mono 用于需要对齐的数据；Noto Sans SC 用于中文。此为待实施方向，具体 Compose 字体族、字重及混排仍需下次定向验证。
- 所有新增字体使正式 APK 增大的总量不超过 **5 MB（5,000,000 bytes）**，以相同构建配置的 APK 前后测量为准。
- 用户要求下次更新其他内容时一起加入，本次只提交资源、预览和交接；不修改运行时默认值，不递增版本或创建 Release。

## 体积事实与中文轻量化

| 文件 | 原始字节 | 内存 Deflate 字节 |
|---|---:|---:|
| JetBrainsMono.ttf | 187,208 | 92,000 |
| Inter.ttf | 876,576 | 471,124 |
| NotoSansSC.ttf | 17,772,300 | 11,333,827 |

Deflate 只用来估算，不是 APK 构建实测。完整 Noto Sans SC 明显超过新增预算，入库文件是**原始设计资源，不是已满足预算的 Android 字体交付物**。下次需要评估静态字重、简体字符集或字体子集，保留许可证并遵循其中的修改及命名要求；未知字符必须有可靠系统后备，不能显示缺字方框。不要只按当前界面固定文案裁剪：用户会话标题、设备名等动态中文同样需要覆盖或回退。

## 下次实施与验收

1. 从最新稳定版本开发，复用 `AppearanceTheme.kt`、`TokenTheme.kt` 和现有界面/总量字体选择机制，保留用户已保存的自定义与系统字体选项。
2. 确定实际打包字重与中文字库轻量化方案，先测新增资源与实际 APK 增量；超出 5 MB 时继续调整，不直接打包完整 Noto 可变字库。
3. 统一普通正文、总量、数据行及图表的字体角色；等宽字体只用于需要对齐的内容，避免全部界面变宽导致布局回归。
4. 保持系统字号和 App 字号设置有效；验证中英混排、数字金额、小数/负号、粗体、长动态标题、生僻字、浅深主题、窄屏及最大字号。需要列对齐时验证表格数字特性。
5. 检查旧字体偏好保留、字体设置切换/恢复、实际 Compose 和图表字形；按 `AGENTS.md` 完成受影响定向测试及联合更新发布。
6. 将实际字体文件、字重、字符覆盖/回退、SHA256、APK 增量和字体许可纳入正式交接及 App 许可清单。

当前未验证：Android 实际字体显示、中文子集覆盖、增量 APK 大小及设备性能。不要把这次预览描述为 App 已完成字体优化。
