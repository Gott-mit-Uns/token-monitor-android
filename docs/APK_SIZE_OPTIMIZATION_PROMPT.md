# 可复制的 Android 包体积优化提示词

请在我的 Mac 上，对 Token Monitor Android 做一次可验证的 APK 包体积优化。仓库是 https://github.com/Gott-mit-Uns/token-monitor-android ，参照项目是 https://github.com/The-Minion-oOo/token-monitor-android 。先读取 AGENTS.md、最新交接、签名与测试规范，以及 docs/APK_SIZE_COMPARISON_064.md；现场核对当前 main、最新正式 Release、版本、签名、未提交修改和原 APK，不把聊天里的旧版本号当作永久基线。保护现有工作，在独立分支／工作区实施。

本次比较参考：我们的 0.2.64/73 APK 为15,238,142字节，SHA-256 df7ab620f0ca9d086ff30da761a232cb5bd99a9053356a3688c61006f1ab8c56；对方 android-v0.70.0-r1 APK 为2,483,408字节。已测差额约93%集中在DEX与字体；对方开启代码/资源缩减并用系统界面字体，这不是本项目能直接达到同一体积的承诺。以实际APK验证收益，不凭配置开关或文件数宣布成功。

先完成同口径盘点，记录 APK 总大小、SHA、ZIP 压缩/解压字节、DEX、字体、图片/XML/resources.arsc、原生库、ABI、语言、签名与封装开销、运行依赖和有效构建配置。区分已测事实、源码说明与推断；不要把“功能类似”写成完全等价，也不要比较不同ABI/语言或AAB下载切片与通用APK。

第一阶段保持产品源码、功能、现有四份字体、全部ABI和语言不变，使用同一提交、同一工具链、版本与签名做可归因的A/B构建，先测R8，再测资源缩减或工具链支持的组合。根据当前实际AGP版本使用官方支持的DSL及keep规则，并从任务日志、mapping/usage/resource报告确认实际生效，不机械照抄对方。若某开关无法单独测试，说明耦合和对照边界。不升级JDK/SDK/AGP，不直接合并旧的R8实验分支。

审计反射、序列化/JSON、动态资源及字体/图标名称查找、Manifest入口、加密缓存和兼容读取所需的最小keep规则。不得用全局保留、全部忽略warning、删除/放宽测试或清数据来制造成功；保留首次失败、当时APK/测试APK指纹、原日志和独立复测。诊断日志和所有报告不得泄露密码、密钥或其他认证信息。

保留只读Hub客户端边界、前台HTTP/SSE与安全选路、认证/TLS校验、可信离线缓存、旧Hub兼容、主页/趋势/额度/设备/会话、字体/主题/语言和About更新入口。不要复制对方Widget Live的轮询或前台服务，不修改Hub/Agent协议、NAS、Lucky、路由或其他生产服务。
