# 跟进安卓上游

当前基础为本分支 `v0.67.0-hub.2`（1bfd0de63e2ac0ae6a559b26b5dc32d45046294e），采用安卓上游0.67→`android-v0.68.0-r1`（bf348606a41e468b534bf097dfd3501f186e9601）的更新。0.67 hub.3和0.68 hub.1～hub.3直接加入的桌面扩展已在hub.4撤下。

安卓是唯一功能更新来源。桌面固定源码用于验证Hub协议和统计含义；桌面发布本身不触发功能移植。现有连接正常时等待安卓上游更新，接口错误或安全问题才提前处理。

## 本地保留边界

中文、黑白图标、独立图标尺寸、主页单位、完整二级数字、主页隐藏趋势、设备页对齐、Hub设备名、NAS／HTTPS域名接入、凭据加密和小组件适配。原应用ID、签名、缓存及 `DisplayPreferences` 的存储键保持兼容。

不再加入桌面扩展设置。历史 `desktop_presentation` 和安卓别名记录保留在设备上，但不参与当前显示，不清除凭据或快照。

## 更新流程

1. `node tools/check-upstream.mjs` 查询安卓稳定Release，只生成审阅提示，不自动合并、发布或升级元数据。
2. 比较已审阅安卓提交到新稳定发布的增量差异；优先网络、系统、小组件与统计修复。本地功能重叠时给用户具体对比。
3. 核对本地保留项；避免直接合并桌面代码。协议DTO、解析、领域模型、历史合并、趋势数据和小组件数据继续使用安卓上游实现。
4. `node tools/check-maintenance.mjs` 验证6份共享核心与已审阅安卓提交相同，检查撤下扩展未重新引入，并比对基础显示设置、安全存储、缓存与Hub地址处理。需要本地Git包含安卓提交和恢复基础提交。
5. 运行协议、统计、偏好兼容、界面与小组件相关测试；用隔离合成数据验证官方Hub，再验证固定签名覆盖安装。只报告实际测试范围。

版本使用安卓基线加本分支后缀。hub.4的versionCode为680104，高于已发布hub.3以支持覆盖安装。不可将恢复版本的内部号降回670102，否则已安装用户无法正常覆盖。

主页面和设置源码仍有必要定制，未来更新仍需审阅这些差异；不宣称已经消除所有合并成本。许可与署名保留，不改用户的NAS或桌面服务。
