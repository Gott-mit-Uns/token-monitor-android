# 安卓上游跟进与本地扩展维护

本分支以 The-Minion-oOo/token-monitor-android 的稳定安卓发布为主要代码来源。桌面 Javis603/token-monitor 只用于核对 Hub 协议、字段含义与统计口径，不要求桌面每次发布都对应一次安卓升级。

当前已审阅安卓版本为 `android-v0.68.0-r1`，提交 `bf348606a41e468b534bf097dfd3501f186e9601`；原始整合基础为0.67。本分支使用选择性整合，未声称已经完整合并0.68上游提交。已验证桌面／Hub为 `v0.68.0`，提交 `5d2db368d8313415763860d594de00e46a663418`。两个来源分别记录在 `upstream.json` 的 `androidUpstream` 和 `desktopCompatibility`。

## 保留边界

本地保留中文、深浅主题黑白品牌与NAS图标、独立图标尺寸、主页万／亿、二级完整数字、Hub设备名、已确认布局、NAS／域名连接与七个小组件入口。原应用ID、签名、加密凭据和缓存保持兼容。

已有字体、排序、模型分组、订阅比较和导出继续使用；不再为了桌面新版本持续扩展。需要删减或让上游替代用户功能时，先展示具体差异供用户选择。

本地偏好兼容层位于 `fork/PresentationPreferencesCodec.kt`；`DesktopPreferences` 保留旧存储键与调用入口。显示处理继续集中于 `ui/DesktopPresentation.kt` 和 `ui/UsageFormatting.kt`。这些名称属于历史代码，不代表必须复刻桌面。

## 更新流程

1. `node tools/check-upstream.mjs` 只查询安卓稳定Release，生成审阅提示；不会自动合并、升级元数据或发布APK。保留PowerShell兼容入口，内部委托同一实现。
2. 比较“已审阅安卓提交→新稳定发布”的增量差异，避免再次移植已经采用的补丁。当前为选择性整合，不依据原始merge-base重放全部0.68提交。阅读安卓发布和提交差异，将变更分成核心修复、系统／小组件适配、功能增加、本地功能重叠四类；优先前两类。重叠需要用户选择时先制作具体对比。
3. 对已共用的历史合并、趋势数据、小组件数据及周期转换继续用同一份上游实现，避免维护第二份算法。`node tools/check-maintenance.mjs` 检查这三份文件及周期转换片段与已审阅提交相同，同时校验来源、兼容版本与构建参数。
4. 选择性移植时记录采用范围。更新已审阅安卓提交前先复核本地扩展；不要把审阅记录说成完整合并。保持上游许可与署名。
5. 运行协议／统计／本地偏好测试、隔离官方Hub合约、Android相关设备测试和固定签名覆盖安装。真实手机、NAS和未覆盖系统的状态按实际证据说明。

## 桌面更新的处理

桌面发布本身不触发功能复刻。现有Hub连接与统计正常时，等待安卓上游。仅在接口不兼容、统计错误、安全问题或用户明确需要某功能时提前修复，并通过固定源码的隔离Hub合约确认；不会在测试中升级NAS或桌面服务。

版本号使用安卓已审阅版本加本分支后缀，例如 `v0.68.0-hub.3`；Hub兼容版本独立记录，版本号不表示桌面全部功能已复刻。

历史上游Android8兼容目标继续保留；本分支尚未实际验证的系统及真机不宣称已通过。
