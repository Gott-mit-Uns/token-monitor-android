# 首页额度与显示设置对照

本轮开发版 0.2.12-dev，versionCode 21，本轮功能与安装验证已完成。桌面基线为 v0.68.0 固定提交 5d2db368d8313415763860d594de00e46a663418。整体桌面一致性与用户体验验收继续进行。

## 本轮行为

首页按桌面规则默认先选剩余额度最紧张的账户，最多 3 个，每个最多 2 个窗口。独立文字模式为默认值，可切换条形模式、选择 1–12 个账户、显示服务名、隐藏首页服务及设置首页服务顺序；恢复默认顺序重新按紧迫程度选择。Antigravity 先过滤隐藏窗口，再挑各模型组的紧迫窗口。Codex 排除额外池，Zed 固定 Unlimited 保留。MiMo 的余额套餐占位、到期状态和产品名均来自 Hub 原始字段与桌面规则。保留完整数字。原始 CSS 首页账户名为 11px，额度标签和数值为 10px，重置说明为 9px，安卓按相同层级实现。

额度页支持服务顺序及逐项隐藏。服务的不同账户共用额度项选择，后续新增项默认显示，数据暂时缺失的已隐藏项仍可恢复。隐藏后重排受影响的半宽窗口，移除空模型组；保留卡片的账户、状态和来源信息。设置只影响本机显示。桌面设置中开启/关闭提供商会控制采集，安卓不提供此动作。

MiMo 的产品记录按账户身份后缀、accountEmail、配置名称及记录键归为逻辑账户，同一账户的 Console 与 Desktop Membership 不计成两个账户。单逻辑账户仍使用服务分组，多逻辑账户再显示账户标题。健康产品以数值和套餐信息识别，状态异常产品保留产品标题。

Hub 的 Codex/Claude resetCredits 显示剩余券数、有效期序列和赠券限制；Claude 预付余额显示赠款金额与到期明细。没有有效券数时不猜测券数。桌面另有从 codex-resets.com 获取的重置券预报，它不属于 Hub 数据，本项目不接入该外部服务。

## 原始来源和可检查证据

capture-limit-layout.cjs 加载原始 windowsView、共用模块和 styles.css，在独立临时浏览器中得到 184 个完整卡片案例和 278 个隐藏项案例，包含两种语言。新增 resetCredits 和赠款案例位于 evidence/limit-preferences；0.2.11 的 164 个历史参考保留在 evidence/limit-layout，历史 APK 和证明不被替换。首次画面检查位于 initial-review，首页账户名修正后重新生成最终证据，首次检查不作为最终安装包的证明。

capture-home-quotas.cjs 原样提取 app.js 中 homeLimitRows、homeLimitWindowLabel、renderHomeLimitModule、formatHomeLimitWindowValue、homeModuleShell 和图标函数，使用原始 homeOverview、windowLabels、usageItems、providerOrder、windowsView 及 CSS 渲染 80 个公开多账户/设置/语言案例。对照包括账户顺序、名称、套餐、窗口标签、值、边界和条形比例。capture-limit-preferences.cjs 则直接调用不可变参考中的排序、隐藏标识、规范化和 MiMo 分组函数。所有静态浏览器只读取白名单原始文件与公开模拟数据，拒绝外部请求，不读取桌面配置或真实 Hub。

最终 92 项单元和 69 项 API36 普通设备检查通过；首页额度专项覆盖深色、浅色、窄屏大字、横屏、平板及关闭动画，既有额度显示/提供商布局和 14 个主要页面各执行浅深色，共 12 份最终页面操作报告。全部绑定同一个最终 APK。已查看首页、窄屏大字隐藏项以及浅色 MiMo/重置券公开截图。

真实 NAS Hub 经 Mac 已有配置的临时 GET 桥接，实际 MainActivity/default 网络客户端核对模式/邮箱遮罩/来源控件、新显示偏好持久化和条件性隐藏项、原始加密快照/历史/账户与前台 SSE。Home 后 3 秒内关闭读取，后台 6 秒无 GET，Launcher 恢复。严格 5 GET（health、stats、history 各 1，stream 2），两条流结束，耗时 19.174 秒。真实名称、数值、响应、像素或 UI 树不归档，凭据仅在上游子进程内存。桥接监听和上游读取已关闭；该检查不能证明实际 Lucky HTTPS或实体手机直连。

0.1.7 与 0.2.11 实际 APK 覆盖到 0.2.12 均通过：保留 UID、Keystore、精确加密缓存/偏好字节及实际 Activity 还原。0.2.11 的 V10 三个 true 额度选项与既有工具、币种、主题和周期恢复，新增 V11 选项使用桌面默认值。V10 读取不重写、V11 全选项与最大 Unicode 项目记录、非法计数/键/布尔/尾字节与原子保存均有设备检查。

## 存储及边界

V11 本机显示记录可读取 V1–V10，读取不重写旧文件。新增服务顺序、隐藏额度项、首页选项写入 AtomicFile；保存前校验已知服务、去重、稳定 JSON 项目键、每服务最多 64 个项目、400 字符上限、1–12 账户和严格布尔值。V11 最大 3 MiB 容纳合法的最坏 UTF 编码，旧版记录保持 4096 字节边界；这些资料排除备份，不包含连接凭据。Hub 原始记录和身份键继续存于独立加密缓存，显示设置不改写它们。

源码核对纠正了前期规划：额度分组没有折叠操作，因此不把“额度分组折叠”当成待补功能。额度数值详情仍可展开，设置区域可收起。安卓保留 48dp 设置触摸目标，并在窄屏/大字体下换行显示完整信息。平台字形、系统状态栏和移动触摸区域不属于逐像素相等承诺。

实际 Lucky HTTPS、实体手机与用户对完整界面的验收仍未完成；不将模拟器测试计数作为产品达标结论。
