# hub.2 维护方向审阅与 hub.3 改进

审阅对象：v0.68.0-hub.2，提交8a35748。参照已审阅安卓上游android-v0.68.0-r1，以及固定桌面Hub0.68协议。范围为来源管理、重复实现、本地设置与回归验证；不是整仓安全审计或全面重写。

| 发现 | 影响 | 处理 |
|---|---|---|
| 更新检查读取桌面来源并提示升级 | 每次桌面发布都形成安卓跟进任务，与收敛方向冲突 | Android稳定Release作为唯一更新提示来源；桌面仅保留兼容证据 |
| 来源元数据混合“基线”和“补丁” | 无法清楚区分原始基础、已审阅版本与实际整合范围 | schema2分别记录安卓来源、原始基础、选择性整合和桌面兼容 |
| 跟进文档停在0.67，还要求保留已停用设备别名 | 容易恢复旧行为或对外宣称错误范围 | 更新维护、安装与发布流程；设备名以Hub为准。清理继承文档中不支持域名、每周桌面跟进和自动发布流程的过期说法 |
| 周期转换多次重新计算相同分类边界 | 与上游重复维护、审阅更困难 | 直接采用安卓上游的周期转换实现；保留既有协议扩展 |
| 偏好解析遇到一个错误字段会恢复全部默认值 | 币种、字体、置顶或排序可能一起丢失 | 读写与校验集中到本地codec，逐字段恢复与旧格式兼容 |
| 缺少防止共享算法再次分叉的检查 | 后续可能继续出现两套历史／趋势算法 | 新增3份共享文件和周期转换的相等检查、来源构建参数检查 |

本轮保留用户界面及现有功能，没有重新复刻桌面、删除复杂功能或完整合并上游。部分UI、协议扩展和历史命名仍与安卓上游不同；这是剩余维护成本，不能宣称已消除全部合并冲突。

本地扩展codec采用旧SharedPreferences名称与JSON键，支持hub.2覆盖安装；字段损坏仅恢复对应设置。非USD汇率损坏且没有同币种有效记录时回退USD，不虚构1:1汇率。整份JSON无法读取时使用默认显示设置，原凭据和快照不在该存储中。

更新流程与源码来源见 [维护说明](../UPSTREAM_SYNC.md)。测试与签名结果写入 [hub.3发布记录](../releases/v0.68.0-hub.3.md)。真机、真实NAS和Android17的未验证项继续保留。
