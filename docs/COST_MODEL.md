# Android 费用口径

适用版本：Android `0.72.0-01` / code76；源码检查基线：`cfab5438ed5dac6537c68affb385517ccfa44c0e`；检查日期：2026-10-17（Asia/Shanghai）。证据来源：`UsageCurrency.kt`、`HubPricing.kt`、`DesktopTokenParts.kt`、`HubSubscriptions.kt`、`SubscriptionPresentation.kt`、`SubscriptionTooltip.kt`，以及该固定提交的 COST_DISPLAY_PARITY 记录。本文是当前规则，测试执行结果只见 [VALIDATION](VALIDATION.md)。

## 来源与单位

Hub stats/history 提供权威用量、已知费用和未定价数量；Android不按价格表重算费用，也不把不同页面/设备或关系摘要再次相加。数量保持精确整数，历史/订阅解析使用十进制金额。USD是用量金额的源币种；价格表五种rate（inputPerM、outputPerM、cacheReadPerM、cacheWritePerM、cacheWrite1hPerM）均为 USD / 100万 Token，缺单价保留未知，显式0才表示免费。缓存读取、缓存写入与一小时写入单价分别显示；实际如何计费由生产端决定，不能由手机重复收费。

订阅金额按来源百分之一货币单位解释；充值、续费、月费和累积支出保留自身含义，不并入历史Token费用。credits余额与spend支出分别展示来源currency，不跨币种相加。Cursor availableCents→USD由采集端除100，Android仅消费归一化余额；余额无分母，不用历史费用反推余额百分比。MiniMax等余额保留CNY/USD原币种。

## 缓存、推理与缺失值

Token分类展示按桌面规则扣除未分类并夹取读取/输出，缓存未命中输入包含缓存写入；原写入字段保留但不得重复加到总量。推理Token及其成本的包含关系由源端模型和聚合定义，Android没有独立推理加价步骤，也不能把已含output的reasoning再加一次。缺少字段/模型定价时保持未知或部分费用，不由默认0伪造完整账单。

工具/模型/嵌套模型取数量、费用、未定价键的并集；已知费用+未定价并存时显示费用不完整，只有未定价且无正已知成本时显示未知。隐藏工具只影响本地列表，不能改变Hub总量。模型别名归并只做展示副本，不改原始模型、缓存或权威合计。

## 币种换算与舍入

显示支持USD/TWD/HKD/CNY，内置比率分别为1/31.5/7.8/6.8，源自固定桌面参考，不是即时汇率；用户可在本机覆盖非美元正数比率，无新增网络汇率源。先用源金额乘显示比率，按JavaScript二进制数值兼容规则取6位，再按USD金额≥10或其他币种≥1显示2位，否则4位。实现用 exact-binary BigDecimal 的 HALF_UP 保持toFixed边界；≥1e21走兼容科学计数法。归属余量减法亦按6位显示语义，只在显示副本进行。

额度、余额、spend和订阅保持来源原币种，价格保持USD/百万Token，不应用用量换算两次。非法、负值、非有限金额显示未知。默认汇率过时、二进制边界和部分定价均是已知限制；本文不承诺源端估算费用等于供应商最终账单。源端费用规则变更先核对合同，再更新本文，禁止记录逐次发布流水。

## 订阅本地派生（只读估算，不是供应商账单）

`HubSubscriptions`把amountMinor用scale2转十进制；订阅周期只接受1–24个月/年，年转12个月。有效覆盖截止优先end，否则未自动续费用start+周期；下一续费从start按完整周期推进到today或以后，有效override优先。记录累计付款为截至有效截止前一天/今天的周期次数×原币种价格；缺自动续费、起始日、周期或价格则未知，未开始为0。充值recordedTotal只计today及以前日期，任一适用金额未知则总计未知。

`SubscriptionReadContext`的供应商月费汇总仅取当前有效订阅，月/年价格除周期月数；充值取当月总计。通过各原币种比率换为USD后再统一显示，缺比率/金额不伪造汇总。月用量来自Hub各工具费用，经固定provider别名映射；当前代码把某工具缺失金额按0参与局部汇总且仅在正值时展示，所以该提示不能被解释为完整已结算成本。用量/月费比值显示1位小数，只是估算性价比，不参与Token总成本。

充值消耗估算从最早充值到today的天数、充值总额和来源余额派生：先经USD换为余额币种（换算6位），充值金额按floor(x×100+0.5)/100保留分，减当前余额再除经过天数；只有正有效分子/天数才显示日消耗，预计剩余天数floor(balance/burn)，日期范围保护保持。该提示的充值总和与recordedTotal日期过滤范围不完全相同，受未来日期记录、过期余额、手动汇率和账号绑定影响，不承诺准确到期。余额显示2位，不能把推算余额或消耗重复加入历史费用。
