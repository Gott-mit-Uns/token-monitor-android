## OpenCode responsibility and evidence boundaries

The PR fixes local session detail retrieval after OpenCode moved from `session/message/part` to `session_v2/session_message`. The token list was already read by bundled tokscale. Current tables are preferred, legacy tables are fallback; migration handling avoids duplicate assistant IDs, reasoning is not added twice, current `idle` and compaction records affect actual activity. Android receives normalized aggregate metadata and does not read either SQLite layout.

The audited clean NAS source checkout at `../token-monitor-nas-072` commit `005bbd2455dcc66c8c3268b23cc89e047db2395f` ports this reader and tests. The parent run separately identified published release `v0.72.0-01` commit `8444a9b1f3aeb88e164fd20b9773a9984d3d33a0`; the fixture execution specifically used the former checkout, not a deployed service. Its release does not establish the user's deployed version. No remote per-turn transcript API is introduced. Android cannot repair missing OpenCode collection or recover unavailable prompt/turn detail; the appropriate fix belongs to the collecting Agent/NAS layer. Older Hub snapshots and absent optional metrics remain compatible; missing metadata must not invent recent activity, calls, cache ratios or timing.

`app/src/test/resources/opencode-072-wire.json` is generated from two temporary synthetic SQLite databases, one per storage generation. `evidence/desktop-072/generate-opencode-fixture.cjs` invokes the NAS source `readSessionMeta`, `buildSyncPayload`, `mergeSyncDeviceRecord`, and `aggregateDevices` and removes the temporary databases. The generator freezes the synthetic pipeline wall clock, including receipt and aggregate-build times, so exact snapshot equality between the storage generations remains a meaningful assertion rather than comparing unrelated generation timestamps. A deliberately later session metadata timestamp confirms it does not override actual message time. Usage counters (150 total, 100 input, 30 output, 20 cache-read, one call) are synthetic aggregate inputs representing the existing tokscale boundary. This is a source-backed fixture pipeline, not a real Agent collection, HTTP transport, actual Hub or phone validation. The separate NAS source tests exercise current/legacy transcript usage, aborted turns and migration deduplication.

## Desktop-only exclusions

Electron auto-download/install/restart controls, footer hover card, progress UI, startup-at-login delay, hourly timers, screen-unlock hooks and desktop window/dock behavior are not portable Android behavior. Android retains its existing explicit browser release notes and system installer flow. No Electron updater parser or local transcript database code is transplanted. Android deliberately does not copy the desktop two-hour timer: only foreground transitions can trigger its throttled anonymous request. Desktop latest-version query remains an independent About action and never drives the Android installed-version comparison.

- Added `OpenCode072CompatibilityTest` for storage-generation equivalence, client/model/title/token/activity preservation, today/month identity deduplication, cold JSON restoration, freshness-only merging, old Hub missing fields and list projection.

The generator now freezes its synthetic wall clock; explicit missing timestamp/turn-ended/calls/cache assertions remain. Full snapshot equality and all token/model/activity assertions are retained.
- Android test/lint execution is coordinated by the parent release run; results belong in the final release handoff. First integrated build exposed a missing BuildConfig dependency in the new model; fixed by using installed package metadata, matching About's existing version source. Keep the first failure log rather than relabeling it as a pristine baseline.
- Final signed candidate, overlay install, screenshots, live Hub/public network, public Release/update metadata and artifact checksum checks remain the parent release gates. No claim of physical-device or production OpenCode validation is made here.

Failure cooldown is persisted alongside the successful-check timestamp; controller reconstruction cannot bypass the one-hour interval. Automatic cancellation writes neither a failure nor a success; manual checks bypass cooldown, and a successful manual check clears failure backoff. Both language About descriptions now explain foreground checks and manual browser/system installation.
