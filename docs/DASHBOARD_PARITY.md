## 页面与数据边界

主窗口趋势图或 ↗ 打开独立 Dashboard，默认总览、30 条、按工具、柱状图。总览与趋势是分别显示的标签，关闭重开恢复桌面默认选择；临时打开本机设置则保留当前标签、范围、模式和已消费的过渡。头部保留返回、只读历史刷新和本机设置，空值与读取失败仍可返回、刷新。

总览八项字段直接使用 lifetime summary；年度热图以本地今天为终点，从11个月前月首起算，Sunday网格，不补入主窗口实时今日计数。模型与工具 Top 5 使用全部 retained daily；条长除以本列最大值，占比除以 daily 总 Token，不能混用 lifetime 或当前30条。摘要根据实际宽度排成二列／四列／八列；排名保留模型在前、工具在后，年度热图可横向查看，点击使用完整精度与真实费用说明。

趋势按最后 N 条实际记录取样，不填充缺日、不把它改成 N 个日历日。堆栈、图例和峰值按所选 attribution 求和，不补未归属；K 线使用每日原总量，桶首尾为实际记录日期。坐标保留52/10/14/24的原留白、五条纵轴刻度、日期抽样和源K线配色/描边。原生触屏详情对应源 tooltip，同时保留未知归属、重复日及未定价说明。

完整桌面 IPC 在 raw Hub history 后追加共享模型别名 presentation。Android 缓存保持原响应，在 Dashboard 前投影整份 retained history；模型堆栈、图例、排行、日详情和 favorite 共享展示身份。规则更新进入渲染事件，不重新下载 history。工具身份仅采用源 `antigravity-cli→antigravity` 规则。原有记录扩展保留 raw history、日历范围、覆盖说明、完整数值、日／月分页和折线图，通过“记录明细”进入。

## 原有过渡与绘制

柱图800ms、K线560ms及源 stagger/Bezier、热图720ms（预隐藏、两次RAF、位置延迟和格子过渡）、排名800ms均来自原renderer。连续更新从实际已绘制几何继续；数据事件与控制选择各自消费一次，纯尺寸调整和设置返回不重新入场。正的系统durationScale固定在段开始，关闭或减少动态效果、后台STOP立即收束。

原生控制条与图例异步布局可能改变图高。当前实现先显示最新控制内容，保持上次提交图形，等两次布局帧后按最终尺寸原子提交目标与事件，再消费源过渡。它是Android布局适配，与热图原本的双RAF各自独立。

每帧状态由Canvas叶子读取，Root与静态轴、标签、图例不订阅每帧值；柱形路径按静态目标缓存。普通stats freshness不重放Dashboard；实际接受history读取递增独立展示事件，即便内容相同，仍对应桌面刷新行为。此计数不是尚未实施的手动请求回执/重试预算身份。

首次真实窗口诊断揭示绘图成本：普通30×8约56.6Hz、全年366×80约15.8–16.3Hz，K线60Hz；指定owner均2次提交。候选APK与每次报告保留在initial-review，不计为最终包通过。密集柱图现采用独立透明条带atlas，目标/颜色/实际像素尺寸变化时静态栅格一次，每帧按原FLIP矩阵批绘；API29以上使用纹理顶点批绘，API26–28走图片条带回退。每柱独立padding防邻柱混入，单张atlas最多8MP，超限使用原vector路径。8MP不是进程或GPU总内存预算，旧显示记录与新图可能短暂并存。普通图保留vector，时间、数据和触屏命中规则保持源语义。原生层缓存与栅格缩放的机制见[Android图形文档](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers)，硬件顶点绘制的API范围见[硬件加速支持表](https://developer.android.com/develop/ui/views/graphics/hardware-accel)。

已保留的性能审查依次为：独立图片条带23.8–28.5Hz；裁剪纹理批绘39.7–41.7Hz；复用单一CCW路径后40.0／49.5／45.8Hz。最后一组稳定绘制中位数约0.35–0.43ms，但更新期绘制最大值64–73ms，完整窗口仍有117–167ms间隔。直接drawRect曾造成缩放后的柱间隙颜色偏差，已恢复原Path.addRect(CCW)+drawPath路径，未放宽像素容差。

当前版本将静态atlas和分配失败后的向量准备放入Default工作线程，逐柱检查取消；在两帧原生布局事务内准备完成后，将模型、缓存、调色板和源动画事件一起提交。旧目标在此期间继续显示，初次进入使用等尺寸占位；过期或取消结果不能发布。实测尺寸回传后复用相同目标，避免第二次准备。三个原像素方法及新增的一项逐像素/取消/旧revision检查均通过。

当前包真实Window九轮已通过，报告绑定APK `4f22df02a038712d25703eb68954c041faed17db77834c0fd09a52496d0e2ae1`。普通30×8完整窗口55.6–56.6Hz，提交后三轮60Hz；全年366×80完整窗口47.8／47.8／48.8Hz，目标提交等待216–238ms，提交后三轮60Hz、最大间隔均16.67ms；K线完整窗口60／55.6／60Hz，中轮仍有一次约50ms间隔。密集图绘制最大值降为24–28ms，超Window截止时间2／3／2帧，指定owner各2次提交。完整窗口包含准备等待，提交后指标不能替代更新响应时间；以上均不是实体手机呈现FPS。完整回归、页面配置和最终封存使用同一APK，详见[原始窗口报告](../evidence/dashboard-parity/final/dashboard-window-diagnostics.json)。
