# 0.2.13 订阅列表、账户关联与套餐详情

本轮继续按桌面端 v0.68.0 实际源码和 DOM 对照；技术检查不能替代用户对功能与界面的验收，项目目标保持进行中。

参考固定在上游 commit `5d2db368d8313415763860d594de00e46a663418`。独立原生 Kotlin/Compose 实现只查看 Hub 已有记录；不增加订阅编辑、删除、提供商登录、采集、Hub 管理或上传接口。

## 具体变化

- 列表采用原始凹陷底色、6dp 圆角、8dp 横向和7dp纵向内边距、13dp图标及11/9/9sp名称、摘要、重新关联提示，列表间距6dp，图标透明度0.85。警告色使用原始语义红色；套餐提示采用原始0.075/0.025表面渐变、0.22边框透明度、7dp圆角和0.54数值透明度。Android提示卡片使用不透明表面合成，不复现桌面窗口背后的系统模糊。Android保留48dp点击区域，并在窄屏和放大字体时显示完整文字。
- 标题优先显示当前Hub账户，套餐名放在摘要。原有账户绑定按账户标识及别名、邮箱、不歧义的名称、唯一账户依次匹配。多账户找不到对应关系时显示原始重新关联提示。名称更新、邮箱遮罩、图标开关在列表和已打开详情即时生效。
- 在额度页点击原有非空套餐文字，可查看桌面悬浮提示对应的费用、续费/到期日期、关闭自动续费、订阅时长和累计金额。没有已记录套餐或原始套餐文字为空时，不增加入口。
- 每账户卡片只显示本账户记录；多账户供应商标题显示汇总。用量是本月Token按API价格换算的等值金额，不能当作待付账单，不能重复归到每个账户。Factory对应Droid、GLM对应Zcode等关系按原提供商目录处理。缩小显示账户集合时，匹配仍基于完整账户集合，金额与用量汇总仍保持同一供应商范围。
- 充值卡片显示最近一笔、本月、完整账本累计、余额、日均消耗和预计用尽时间。完整账本与余额使用各自币种，并按当前本地汇率换算后比较；余额高于记录充值、不足以计算消耗、未知币种或字段缺失时不捏造预测。日历/金额文本直接与原始模块结果对照。
- 初次进入额度页允许前台读取一次Hub订阅记录，同原有订阅页共享已加载缓存及修订。读取使用原有白名单GET、取消与Keystore缓存路径，未新增轮询或后台连接。
- 缺少唯一ID的同名记录按账户绑定区分，调整顺序不会把已打开的记录切换到另一个账户。

## 参考生成方式

`tools/capture-subscription-accounts.cjs`直接调用原始`renderer/accountIdentity.js`和`shared/subscriptionDisplay.js`，覆盖33组去重集合、2376组绑定结果，以及键别名的传递合并、同邮箱多工作区、轮换标识、名称歧义和唯一账户回退。

`tools/capture-subscription-layout.cjs`在独立静态浏览器中执行原始订阅列表函数和原始`createLimitWindowsView`，读取72组实际列表DOM和144组实际套餐提示DOM。后者涵盖USD/CNY、英中语言、独立账户/供应商汇总/缩小显示集合、未来/结束/取消计划、充值账本与余额换币、Factory/Droid和GLM/Zcode用量归属。参考截图来自这些公开合成记录。浏览器阻止远程资源，请求仅限原始静态资源；未打开真实用户配置或数据。

结果保存在`app/src/test/resources/subscription-accounts-parity.json`、`subscription-layout-parity.json`及测试专用资源中；发布应用不携带这些测试数据。界面措辞模板由原始英中翻译生成，未知字段仍保留缺失状态。

## 后续边界

订阅编辑和账户重新关联在现有桌面端进行，安卓只显示已有记录和必要提示。实际Lucky公网入口、实体手机网络和功耗、正式签名/更新通道仍需各自的真实验收；模拟器和LAN桥接不能证明这些条件。

桌面其他本机专用选项继续按Hub查看器范围审查；不因本轮对照通过就宣称整个安卓端已经与桌面完全一致。
