# 背景图片：实施计划与验收基线

状态：0.2.40 已实现并完成公开验证，实际结果见 [BACKGROUND_IMAGE_PARITY.md](BACKGROUND_IMAGE_PARITY.md)。以下保留实施前差异与验收要求；0.2.39 真实 Hub 和覆盖升级报告仍保留原包范围。

## 原始依据与当前缺口

原始 index.html 的 appearanceSettingsDetails 包含背景图片状态、选择、移除、透明度和恢复按钮，位于“外观”，不是 window 分组。styles.css 的 .shell.has-custom-background::before 将图片作为独立层：居中、cover 裁切、图片上叠背景色 18% 的蒙层，整体透明度默认 28%。该透明度不替代背景颜色或玻璃透明度；原始特定原生不透明/减少透明度状态隐藏图片层但保留选择。

当前 Android AppearanceSettings 只有主题预设、颜色、字体、文字大小及厂商颜色，没有图片选择和透明度。不能把该差异归为无关的桌面窗口机制。主页 Token 动效、Hub 读取和缓存均应继续保留。

## Android 实施边界

- 使用系统图片选择器，仅访问用户选择的单个图片，不增加广泛媒体读取权限；不读取 Hub 图片或增加后台网络。
- 图片保存到应用私有且不参与系统备份的本地存储。解码和尺寸/体量控制在后台工作线程完成；取消、解码失败或保存失败保留之前的图片，不记录原文件路径/名称或图像内容。
- 在应用内容下增加独立图片层，按原始 cover/居中/18% 背景色蒙层/28% 默认透明度显示；图片层不接收触控、不占可访问焦点、不改变内容尺寸。不得通过降低数据文字透明度来实现图片透明度。Android 的普通不透明背景不等同于 Electron 的原生材质 opaque 状态，不能因此永久隐藏图片。
- 外观设置保留选择、当前状态、移除、0–100 透明度及恢复 28；未选择时隐藏移除与透明度。中英文文案沿原始含义，取消选择保留原图。
- 图片与透明度是本机显示选项，不写 Hub；资料格式兼容既有偏好，不因加载或无关设置改写旧资料。
- 清除图片移除私有图片与当前显示状态；图片加载不触发 Hub GET，后台/选择器打开时仍按原生命周期关闭 SSE。

## 必须验证

1. 使用公开合成图片核对实际渲染：默认 28、0、100、18% 蒙层、居中 cover，以及浅深主题下的尺寸和触控。
2. 选择后保存、Activity 重建、再次启动、取消、失败、移除与透明度恢复；此前旧偏好和加密 Hub 缓存保留。
3. 图片处理为有限任务，尺寸和体量边界不会无界内存分配；失败不替换旧图或旧资料。
4. 图片层不截获日历、会话、菜单、刷新和主页总量操作；Token 连续更新、减少动画及后台返回保持。
5. 外观六配置与主要页面重新记录；所有新图像为公开样例，实际用户图片不进入证据。

实际 Lucky 和实体手机是另两个验证缺口，本功能开发不依赖手机当前可连接。
