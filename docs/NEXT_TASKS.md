## 保留的验收缺口

以下是待另行安排的验证，不是立即开发或操作生产服务的授权。

| 范围 | 当前边界 | 后续验收条件 |
|---|---|---|
| 实体手机升级及历史保留 | 模拟器公开合成缓存、历史及选定偏好升级已记录；不代表用户全部私有数据真机通过 | 核对旧包、正式签名与恢复方式后，覆盖安装、启动并检查历史和设置；不卸载或清数据 |
| 真实手机网络与生命周期 | LAN / HTTPS / 蜂窝、锁屏、省电及 OEM 后台仍有未验证范围；历史首次失败保留 | 检查同 Hub 双入口准入、认证/TLS封锁、前台恢复、单 SSE 与旧响应隔离；不以主机代理验证代替手机直连 |
| Cursor X 与新 provider 数据 | 客户端合成样例通过不证明真实账号额度、余额或生产新字段可用 | 在单独授权的只读联调中确认账号、单位、时效、缺失字段与真实零；不新增手机认证或采集 |
| OpenCode 2.x 实际采集链 | 新旧 wire 样例覆盖 Android；不等于真实 Agent 数据库恢复及上传端到端验证 | 分开验证 Agent → Hub 产出与 Android 消费；不在手机移植数据库采集 |
| Hub 名称与能力 | 客户端支持可选鉴权名称；NAS 代码发布记录不代表实际部署已验收 | 读取真实能力及字段；缺名称/未知/离线继续诚实降级，不硬编码设备名或在线状态 |
| 大数据性能 | 既有容量及 freshness 局部结果不等于实体手机流畅度 | 按[性能计划](HUB_CAPACITY_PERFORMANCE_PLAN.md)验证可归因的 full frame、导航、保存与冷恢复；不缩小样例、提高堆限制或扩大通过范围 |
| 上游尚缺远程合同的能力 | 会话正文、批准原因、Grok 跨历史增强等不因 UI 相似而完成 | 先确认 Hub 明示数据合同，再决定客户端是否需要增量；见[功能矩阵](FEATURE_MATRIX.md) |
