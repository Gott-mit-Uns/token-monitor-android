# 桌面外观背景图片

当前封存 0.2.40-dev / code49，整体目标继续进行。对应原始 appearance 分组的图片选择、状态、移除、独立透明度和恢复入口。

## 实现与原始依据

原始 styles.css 将图片居中 cover 裁切，在图片上叠背景色 18% 蒙层，再对整个图片层应用默认 28% 透明度。安卓使用同一合成顺序，独立图片层位于内容下方，不接受输入、不进入可访问焦点，不改变文字透明度。普通不透明 Android 背景不等同于 Electron 原生 opaque 材质，图片仍可显示。

系统 OpenDocument 选择器只请求 image/*，没有新增广泛媒体权限、Hub 图片接口或网络任务。图片读取/解码/转换/保存位于工作线程；沿原始 backgroundImage.js 的 12MiB 输入、8MiB PNG 和最大边 2000 限制，先检查尺寸再分配。API28以上 ImageDecoder 处理方向与缩放，API26/27 有限采样后按 EXIF 方向变换。后者尚未作为旧系统实机通过；不泛化 API36 的结果。

独立 no_backup 私有原子记录保存 PNG 与透明度；已有 V16 显示偏好和加密 Hub 格式不变，图片不进入主题编码或同步。取消/解码失败/保存失败保留旧图；保存失败回退已提交透明度。移除删除图片字节并保留独立透明度，恢复按钮回到 28。跨实例共享磁盘锁避免 AtomicFile 的 .new 文件互相干扰；过时请求不提交，模型销毁使旧请求失效。

本地化上下文并不保证持有 Activity，图片模型从实际 Lifecycle/ViewModelStore 宿主获取；同样修正系统栏主题更新的宿主获取。选择器打开后的 SSE 继续遵守原 onStart/onStop，没有背景网络或常驻服务。

## 公开验证与问题记录

深色三项图片专项通过：实际 OpenDocument 合约及结果回调、取消、失败保留、0/28/100像素、18%蒙层、中心 cover、透明度保存/恢复、移除、Activity重建与新模型加载、EXIF方向、超限及跨实例原子读写。图片层下总量操作和无额外Hub读取验证通过。透明度像素证据是实际共享图片层的独立渲染；主页和设置另有完整原生画面，不把两个范围混称为整页像素相同。

原始完整 renderer/preload 使用同一张公开 Java/Android 样例 PNG，新增中英文28/100/0/移除四状态，现共42张原始整页；167个renderer依赖加单独backgroundImage.js指纹。原始CSS实际opacity为0.28/1/0，大小cover、位置center与无输入由计算样式保留。

测试提供器最初使用Kotlin，在独立测试APK进程缺少该运行库，已改为仅Android/Java；另修正了测试未提供外观编辑回调与生产本地化上下文的宿主获取。安全诊断保留；不新增生产提供器或依赖。所有图片为公开红绿蓝样例，不接触用户图片。
