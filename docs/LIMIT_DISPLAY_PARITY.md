# 额度、账户隐私与模型标记

2026-10-10，开发版0.2.10-dev（code19）。固定参考桌面v0.68.0提交5d2db368d8313415763860d594de00e46a663418；保留0.2.9及此前只读查看行为。整体目标仍在进行，技术结果不代替用户体验验收。

## 已接入行为

设置增加本机额度显示方式（剩余/已用）、账户邮箱遮罩与来源显示。默认值按桌面为剩余、不遮罩、不显示来源。首页与额度页共用同一套选项；订阅列表、详情标题和备注中的账户邮箱也遵守遮罩。显示切换不写入Hub，不修改原始账户记录或订阅绑定。不存在因显示开关触发的厂商登录或采集。

解析保留每条提供商记录的位置、邮箱、账户名、套餐与稳定身份种子，窗口保留usedPercent/showMeter/limitId/resetDescription/additional、来源与可用balance。窗口按原提供商记录分组，解决两个Plus账户被合并的问题。多个账户使用单个提供商标题，账户名与右侧套餐分别展示；Codex无身份时显示Account N，不把Plus/Pro当作账户名。遮罩造成的同名使用桌面工作区/名称及最短可区分的散列后缀；非散列种子先按FNV-1a变为不透明标记，不回显身份字符。计划字段兼容OpenCode、API、Volcengine与MiMo的已核对命名规则。

百分比以remainingPercent为统一锚点，usedPercent仅作缺失时回退；数值和进度条同时按显示方向变化。缺失或非法数值保持未知，不补为0。额度金额按来源币种保留完整数字与两位小数，USD/CNY/CREDITS或其他代码按桌面规则显示。消费窗口显示已用金额及可用上限，金额型标题不翻转成已用比例。余额无固定上限时，按原函数由余额与观察到的月消费推导仅供显示的进度；不把推导结果写回Hub。

Command Code、Kiro、Qoder、Zed、GLM/Team和Kimi的绝对数值副行按对应窗口类型处理；不将任意detail重复显示到所有进度条。Kiro超额消费、不限量和showMeter=false保持无进度条。来源标签按提供商细分，例如Codex App/CLI/Managed、Grok RPC显示CLI、Volcengine CLI显示arkcli。来源开关同时控制来源设备和展开窗口的来源。前台页面按分钟更新相对时间；重置、到期及混合边界分别表述，后台不继续页面计时或网络读取。

窗口标题与百分比在空间允许时沿用桌面同一行排列；大字或长数值换行。单窗口与账单/消费窗口占满行，双窗口并排，窄屏大字改为单列，金额与身份不截短。Home采用桌面紧凑窗口选择：Codex不混入additional窗口，Antigravity选择紧迫窗口及最多两组，Zed不限量预测窗口移除不适用备注。

模型unknown只有整份桶被Codex覆盖且其他来源没有非零/非法计数时采用Codex标记；检查原始clientModels，避免过滤坏值后误判。其他未知模型用桌面Σ图形，未明确来源的unknown用色点，关闭列表图标时仍用色点。Grok额度使用grok.svg对应图形，普通工具继续使用xai.svg；原图许可与来源归属保留。

显示偏好V10在V9之后追加三项严格布尔值，V1–V9可读且读取不重写。既有厂商色、图标/状态点、主题/字体、币种比率、首页和工具选项保留。连接与原始Hub缓存仍采用此前加密记录格式，不加入依赖。

有意保留完整数字，GLM计数由桌面注入式formatter使用完整数值而非缩写。额度金额没有可识别币种时保持未知，不猜USD。非规范化坏值从严处理，避免把缺字段或坏计数装作真实数据。以上与正常有效桌面参考值分别验证。
